# V5 离线诊断

V4 的私有远端提交是 479411b154c77166e90358d7369c016bf9a6c41e，本地历史提交 057ce5b 的文件树与它相同。复验了 V3/V4 冻结文件的哈希、40 份中断快照和 280 条有评分的历史轨迹。新增实验启动前，账本占用上界为 2.770144776 美元，含三笔未结预留。

## 结构失败与真实证据

V4 的 C+ 首次失败 21/40，修复成功 2 条，最后回退 19 条。纯数字步骤规范化可救回 13 条，合并同一步、同一状态的回执再救回 2 条。用全部历史响应测试时，原解析器完整通过 21/40，表示层规范化后完整通过 36/40。加入独立的证据核验和局部保留后，C5 得到 25/40 完整状态、15/40 局部状态、0/40 回退。按每题最完整的历史响应统计，意图、证据和编辑模块分别为 40/40、26/40、38/40。局部状态已经降级过不可靠内容，不能算作完整通过。

例如，0 把原步骤号写成字符串，属于同一数字的两种表示。244 把交易对象 ID 当作回执 ID，程序不能据此推测回执。9 和 309 把同一步的证据分成多行，状态相同，可以合并引用。V4 的分数保持原样。

## Guard 覆盖和标签边界

V4 的正式 C++ 没有产生规则。40 条中有 16 条回退、16 条待执行 API 无规则、8 条的细化条件未满足。六种继续方法共 689 次实际执行且返回 2xx 的调用，其中 **505 次应用侧、184 次 supervisor 调用**。早先诊断答复误把一条 supervisor 调用归入应用侧，给出了 506。35 个阳性全属于 supervisor，应用侧没有观测阳性。40 条边界探针阳性中，31 条属于应用侧。

689 条自然调用中有 304 条可贴标，包括 35 条观测阳性和 269 条经核对的只读或无答案完成负例。其他 385 条保持未知。未观测到违规的写入没有自动贴负例。边界探针单独报告，不能反映自然发生率。真实 pilot 机制控制和手写对照也分别报告。

导出、预测和汇总由不同的 Python 进程执行。预测脚本只收检查过字段的输入文件，候选请求本身的回执和评分写到另一份标签文件。预测器没有接收独立修订指令、评分器、模拟器隐藏状态或未来回执。进程共用工作账户，未建立操作系统权限沙箱。
