# V5 独立评分审计

正式主结果始终使用冻结的 InterventionBench 评分。审计只从已保存的终态数据库建立副本，单独输出版本 compatibility_audit_v1。各方法连同从头做的 D 使用同一调整。代码与 Guard 分离。

| 干预 | 查实的问题 | 敏感性规则 |
| --- | --- | --- |
| 263 | 评分器用单数 relationship 查同事，固定版本的联系人使用 relationships 列表。AppWorld 点赞时还会维护交易的 like_count。除此之外，历史七组确实都达到调用限制。 | 用实际字段识别同事。只接受已有交易的点赞计数和更新时间变化，继续检查正确的目标集合和未点赞自己发出的交易。 |
| 267、272 | 保存的终态中各新增一条对方收到请求的通知。官方重放包装会向 changed_model_names 注入 Notification 忽略名单，而这两题又明确要求 Notification 出现在差分集合。 | 用显式 include 重新把 Notification 加入被比较的集合，并保留原其余模型差分要求。没有删除通知断言。 |
| 737 | 用户撤销退货，但冻结评分仍要求新增退货记录、匹配原订单和原商品。此外第二个模型范围断言漏掉了同一评分器前一个断言允许的购物车变化。A 还有独立的商品和数量问题。 | 明确检查退货状态没有变化。已撤销的退货订单及商品元数据不再适用。将评分器原有的购物车、地址排除项一致应用，两处商品和数量检查继续保留。 |
| 763 | 有语义歧义。「发修正后的金额」可以理解成付款。六种续跑做了真实付款，D 发了新付款请求，符合冻结断言。 | 保持评分，单独解释付款与请求付款的差别。 |

可核验文件包括 [评分审计脚本](../scripts/v5_evaluator_audit.py)、[各方法新旧断言及成绩](../results/harness_v5/evaluator_audit.csv) 和 [独立评分版本](../results/harness_v5/evaluator_audit_version.json)。未单独标注的保留约束报告为 N/A，不能由部分通过的重叠断言推断为独立保留成功。
